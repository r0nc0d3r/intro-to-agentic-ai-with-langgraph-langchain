# Contributing

Thanks for your interest in contributing!

## Workflow

- `main` is protected — all changes must go through a pull request; direct
  pushes are rejected.
- Create a feature branch, commit your changes, push, and open a PR
  against `main`.
- Fill out the PR template (summary + test plan) when opening a PR.

## Commit messages

- Use the imperative mood in the summary line (e.g. "Add", "Fix",
  "Update" — not "Added"/"Fixed").
- Keep the summary line concise (roughly 50–72 characters).
- Add a blank line followed by a short body explaining *why* the change
  was made when the reason isn't obvious from the summary alone.
- Keep each commit to one logical change where practical.
